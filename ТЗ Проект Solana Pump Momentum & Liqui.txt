### 1. ОСНОВНЫЕ ХАРАКТЕРИСТИКИ ТОРГОВЛИ:
- Высокочастотный скальпинг (High-Frequency Scalping): средняя длительность удержания позиции составляет всего 1–3 секунды.
- Динамика сделок: быстрый вход на импульсе объема и мгновенная фиксация прибыли или сброс позиции при малейшем затухании импульса.
- Высокие требования к проскальзыванию и приоритету:
  * BUY_SLIPPAGE_PCT: 20.0% (жестко заданный запас на покупку для мгновенного исполнения).
  * SELL_SLIPPAGE_PCT: 25.0% (динамический запас на мгновенный сброс).

### 2. ПОДКЛЮЧЕНИЕ К SOLFEED / WEBSOCKET:
- Реализовать асинхронный менеджер WebSocket-соединений (`core/client.py` и `core/listener.py`).
- Подключение к Solfeed / Helius Geyser WebSocket для потокового получения:
  1. Логов программ (Program Logs / LogsSubscribe) для Pump.fun и Raydium.
  2. Изменений состояния аккаунтов пулов (AccountSubscribe) в режиме реального времени.
- Обработка разрывов связи: авто-реконнект с экспоненциальной задержкой (Exponential Backoff), минимальный overhead при сериализации/десериализации JSON/Borsh.

### 3. ЛОГИКА И КРИТЕРИИ ВХОДА (ПОКУПКА / BUY):
Вход выполняется только при УСПЕШНОМ прохождении ВСЕХ следующих фильтров подряд:
1. Liquidity Guard (`filters/liquidity_guard.py`):
   - `pool_sol >= MIN_POOL_SOL` (по умолчанию 30.0 SOL).
   - `Price Impact` одного ордера <= 5.0%.
   - Расчет `min_tokens_out` с удержанием `BUY_SLIPPAGE_PCT = 20.0%` по AMM-формуле constant product ($x \cdot y = k$).
2. Security Guard (`filters/security_guard.py`):
   - `Freeze Authority == None`, `Mint Authority == None`.
   - Проверка LP Burn / Lock (> 90%).
3. Momentum Trigger (`strategies/momentum_pump.py`):
   - `Buy/Sell Ratio >= 0.70` (более 70% сделок за последние 3–5 секунд — покупки).
   - `Volume Velocity >= 1.5 SOL` суммарных покупок за 3–5 секунд.

### 4. ЛОГИКА И КРИТЕРИИ ВЫХОДА (ПРОДАЖА / SELL):
Учитывая таймфрейм позиции в 1–3 секунды, реализовать 3 параллельных триггера выхода:
1. Micro Take-Profit / Trailing Stop:
   - Каскадный фиксированный Тейк-Профит (+30% / +50%).
   - Скользящий Трейлинг-Стоп: если цена достигла локального пика и откатилась на 8–10%, выбивать сделку немедленно.
2. Emergency Stop-Loss (Жесткий стоп):
   - Падение цены на -12% от точки входа.
3. Volume Exhaustion / Adverse Flow (Затухание импульса):
   - Появление хотя бы одной крупной продажи ($> 1.0\text{ SOL}$) или резкое падение Buy/Sell Ratio ниже 0.40 за последние 2 секунды.

### 5. КРИТИЧЕСКИ ВАЖНЫЕ ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ:
1. Низкий Ping и оптимизация задержек (Latency):
   - Использовать асинхронные HTTP/WS сессии (`aiohttp` / `websockets` с `uvloop`).
   - Использование микросекундных таймеров для замера задержек RPC/Node.
   - Поддержка настройки Compute Budget (Priority Fee / Micro-lamports) для гарантированной вставки транзакции в ближайший слот Solana.
2. Анти-сэндвич и защита через JITO Bundles:
   - ВСЕ транзакции входа и выхода ДОЛЖНЫ формироваться и отправляться в виде Jito Bundles через Jito Block Engine API (`core/executor.py`).
   - Добавление обязательной инструкции чаевых валидатору (`JITO_TIP_SOL` = 0.005 SOL) для защиты от MEV-ботов, сэндвич-атак и исключения зависания транзакций в мемпуле.
