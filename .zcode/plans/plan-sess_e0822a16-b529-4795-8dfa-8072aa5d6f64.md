## Контекст

Проект зрелый: весь библиотечный слой (транспорт → листенер → фильтры → стратегия → исполнитель → портфель → бэктестер) готов и согласован, но бот нельзя запустить (нет `main.py`), тестов нет, Jito-бандлы не подтверждаются после отправки, позиции живут только в памяти, а `max_concurrent_positions=1` захардкожен в `LivePipeline`. В корне 17 `.tmp_*` файлов (один на 45 МБ) и мёртвые константы.

**Ключевые решения:**
- **БД** — SQLite (`sqlite3`, stdlib, без новых зависимостей), WAL-режим. Память остаётся быстрым путём для скальпинга, БД — write-through надёжный слой: рестарт восстанавливает открытые позиции, и бот продолжает управлять выходами (TP/trailing/SL/max-hold работают по позиции + снимку пула даже с пустыми окнами индикаторов).
- **Подтверждение Jito** — после `sendBundle` опрос `getBundleStatuses` (есть в core/jito.py:273, сейчас мёртвый код) с фолбэком `getSignatureStatuses` через RPC. Позиция открывается только после `Landed`; таймаут = ордер не принят, с CRITICAL-логом подписи.
- Порядок работ: git init → чистка → верификация → конфиг/персистентность → Jito → main.py → тесты → финальная проверка.

## Шаги

### 1. Git и чистка
- `git init`, первый commit текущего состояния (проверив, что `.env` в `.gitignore`).
- Удалить 17 файлов `.tmp_*` в корне.
- `utils/constants.py`: убрать мёртвые константы (`RAYDIUM_CPMM_PROGRAM_ID`, `SERUM_V3_PROGRAM_ID`, `OPENBOOK_PROGRAM_ID`, `RAYDIUM_SWAP_BASE_IN/OUT_DISCRIMINATOR`, `JITO_MIN_TIP_LAMPORTS`, `PUBLIC_MAINNET_RPC`, `PUMP_GLOBAL_SEED`, `PUMP_EVENT_AUTHORITY_SEED`) — каждую перепроверить grep'ом перед удалением.
- `requirements.txt`: убрать `numpy`, `pandas` (не импортируются); убрать их mypy-overrides из `pyproject.toml`.
- `.env.example`: дополнить новыми переменными (ниже).

### 2. Верификация кода (до изменений)
- `python -I -m compileall` — синтаксис всех скриптов; `ruff check`; `mypy`; `vulture` — мёртвые функции/методы; вручную — мусорные тернарники и clamp-и (`clamp_sell_fraction`, `max()` в `_finalize` и т.п.). Исправить найденное.

### 3. Конфиг (config/settings.py)
Новые поля: `max_concurrent_positions: int = 3`, `capital_sol: float | None = None`, `portfolio_db_path: str = "data/bot.db"`, `jito_require_confirmation: bool = True`, `jito_confirm_timeout_seconds: float = 10.0`, `jito_confirm_poll_seconds: float = 0.5`. `LivePipeline` читает их из `settings` (конструкторные параметры остаются как override).

### 4. Персистентность позиций
- Новый `core/persistence.py`: `PortfolioStore` на `sqlite3` (WAL, `synchronous=NORMAL`), схема: `positions` (PK `base_mint`, `status open/closed`, `pool_address`, `dex`, `entry_price`, `entry_sol`, `token_amount`, `initial_token_amount`, `opened_at`, `peak_price`, `tp1_taken`, `realized_sol`, `signature`) и `closed_trades` (все поля `ClosedTrade`).
- API: `upsert_position`, `record_closed_trade`, `load_open_positions`, `count_open_positions`, `open_positions_snapshot`, `close()`.
- core/portfolio.py: интеграция write-through (открытие / частичная продажа / TP1 / force close / новый пик — запись в БД) + `PortfolioManager.load_open_positions()` для рестарта. `ClosedTrade` также пишется в БД.
- core/pipeline.py: на `start()` — восстановление открытых позиций из БД с WARNING-логом; dry-run использует отдельный путь БД (`data/bot_dry.db`).

### 5. Подтверждение Jito
- `core/jito.py`: метод `await_bundle_confirmation(bundle_id, timeout, poll_interval)` → статус/слот/ошибка.
- `core/executor.py` `_assemble_and_send`: после отправки — подтверждение; `Failed`/таймаут → `OrderResult.success=False`.
- `models/trade_data.py`: в `OrderResult` поля `confirmed: bool = False`, `landed_slot: int | None = None`. В core/trader.py позиция открывается только при `confirmed` (dry-run не меняется — подтверждён всегда).

### 6. Точка входа `main.py`
- argparse: `--dry-run`, `--watchlist MINT...`, `--positions N`, `--capital SOL`, `--log-level`, `--close-on-stop`, `--status` (только показать открытые позиции/PnL из БД и выйти).
- `asyncio.run(LivePipeline(...).run())`, uvloop на POSIX, graceful shutdown по SIGINT/SIGTERM + KeyboardInterrupt, лог-сводка на выходе.

### 7. Тесты (tests/, pytest + asyncio_mode=auto)
`test_amm.py`, `test_filters.py`, `test_indicators.py`, `test_strategy.py` (вход/каскад TP/trailing/hard SL/exhaustion/max-hold), `test_portfolio.py` (лимиты, частичные продажи, рестарт из БД — tmp_path SQLite), `test_persistence.py`, `test_decoders.py` (синтетический TradeEvent), `test_jito_confirm.py` (мок-клиент), `test_backtester.py` (мини-CSV).

### 8. Финальная верификация
`pytest -q`, `mypy`, `ruff check`, прогон `python -I main.py --dry-run --status` (без сети) — и коммит.

**Не трогаю:** Raydium direct-swap (реально используется Jupiter fallback — пометка в README), `simulate_transaction` (вне скоупа этой итерации; README переформулирую).

## Проверка
1. `python -I -m pytest -q` — все новые тесты зелёные.
2. `python -I -m mypy` и `ruff check` — чисто.
3. `python -I main.py --status` — читает БД, работает без RPC.
4. Smoke: `python -I main.py --dry-run` на реальном RPC — события идут, позиции пишутся в `data/bot_dry.db`, рестарт восстанавливает позиции, Ctrl+C закрывается чисто.
